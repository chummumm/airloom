# Airloom 0.4.1

## 应用和设备自动更新

- 应用列表订阅 Windows 音频会话创建、状态变化、断开和进程退出事件；启动时读取一次，之后没有周期性补查。
- 扬声器发现改为持续订阅 AirPlay/RAOP 服务的新增、更新和移除事件，正确合并同一物理设备的两种服务。
- 保留手动刷新。刷新不会改变已选应用、重启正在播放的连接或自动选择新设备。
- 应用选择器复用已有选项；下拉框打开时延后增删，保留焦点与选择。已退出应用不会被其他应用或系统声音替代。

## 已有 HomePod 原生立体声组合：试验性兼容

这是路线 A：先在 iPhone/iPad 的“家庭”里建立组合，再由 Airloom 识别和播放。

- 根据 HomePod 的有效原生组合标识识别成员，在界面显示一张组合卡，可展开成员状态。
- 两台都就绪后才开始发送完整双声道，使用共同起播时间线；一台失效时整组停止并重新连接，不静默丢掉一边声道。
- 密码与配对仍按成员处理；现有总音量同时控制组内两台。只选择一个组合时界面显示“组合音量”。
- 选择组合后，测试音改为先左、短暂静音、后右，共 3 秒。
- 隐藏过的成员不会因合并成组重新出现在主页；在设置中恢复组合会同时清除成员隐藏状态。

**这项功能尚未完成真实 HomePod 双机验证。** 本地协议测试覆盖双接收端的完整双声道、共同 RTP/播放时间映射、延迟协商和异常整组停止；这些结果不能证明所有 HomePod 固件兼容或实际声学同步。界面明确标为“兼容性验证”。无法满足共同 PTP 时钟条件时会显示协商失败，不降级成两台无约束独立播放。

没有实现软件左右声道分流，也不在 Airloom 内创建、拆散或修改 Apple“家庭”组合。Apple TV 家庭影院绑定组合属于另一个待验证场景。详见 [立体声说明](https://github.com/chummumm/airloom/blob/main/docs/stereo.md)。

## 版本编号

后续按照 `0.4.1 → … → 0.4.9 → 0.4.10 → 0.5.0` 递增。发布流程校验相邻版本，拒绝跳号；构建校验程序、安装包、资源和更新器版本一致。更新器以整数比较各段，因此 `.10` 正确大于 `.9`。

## 验证与使用

构建流程检查 Rust 协议/音频测试、Windows 进程采集和事件订阅的真实 API 生命周期、WinUI 自动更新交互、组合界面、原生更新退出与包清理。Release 只从完整成功的 Windows/Linux 构建发布，随附界面证据及 API 检查记录；fixture 中的应用、扬声器和信号均为测试数据。

Windows 11 x64；无虚拟声卡驱动。安装版可使用设置中的“检查更新”，或者完整解压便携包后运行。0.2.1 及以后版本支持安装前正常退出；更早版本请先在托盘菜单中退出 Airloom。
