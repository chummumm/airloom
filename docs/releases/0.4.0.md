# Airloom 0.4.0

这一版重新整理原生按钮，并新增免驱的指定应用音频投放。

## 按钮与操作

- 统一主操作、次操作、紧凑操作、轻量操作和图标按钮的字号、间距、圆角与状态反馈。
- 开始／停止投放使用更紧凑的主按钮；试播、检查更新、复制诊断有清楚的操作边界。
- 保留原生键盘焦点、悬停／按下／禁用状态，以及系统动画偏好。
- 固定播放栏和音量数字槽位继续保持稳定。

## 只推流一个应用

1. 顶部声音来源选择 **指定应用**。
2. 让目标应用播放一段声音，然后点击 **刷新列表**。
3. 选择应用，再选择扬声器并开始投放。

基于 Windows 原生进程 loopback，采集所选进程及其子进程；无需安装虚拟声卡驱动。应用暂停后可以继续保持选择。同一个浏览器实例的标签页属于同一应用，当前不提供单独标签页选择。

切换声音类型会停止当前投放，保留扬声器选择。指定应用需要手动选择，目标退出后不会自动改播其他应用或系统声音，重新启动的实例需要重新选择。应用模式下电脑整体静音不可用，本机正常播放保留。系统声音模式和已有 HomePod 认证、音频发送路径继续使用。

## 多设备与立体声

现有多设备功能向每个接收端发送完整双声道音频。它不等于 Apple 原生左右声道组合。

Apple 的原生组合需要在 iPhone/iPad 的“家庭”中，把同房间的两台同型号 HomePod 配对。本版未实现 Windows 内创建、拆散或交换原生组合，也未完成已有组合的实机验证；不会把未验证的行为显示为可用开关。详见[立体声支持边界](https://github.com/chummumm/airloom/blob/main/docs/stereo.md)。

## 验证与运行

适用于 Windows 11 x64（build 22000 或更新）。继续提供安装版、便携版及 SHA-256 校验。

发布检查包括原生深浅主题、实际音量拖动、应用选择／切换与空状态、设备密码弹窗和更新退出检查。应用展示截图采用明确标注的测试数据。真实 Windows API 测试检查进程采集激活、身份校验、取消和退出处理；它不替代两应用同时播放时的声音隔离实测或 HomePod 听音。

0.2.1 及更新版本可使用应用内更新。更早版本请先从托盘退出，再运行安装包。
