# Airloom 0.4.3

## 音量跟随扬声器

- 连接时读取接收端 `/info` 返回的 `initialVolume`，以设备原有音量作为界面读数。启动、连接、重新连接及切换音源不再自动发送默认音量。
- 不在本地保存或恢复另一份音量。只有用户明确调节滑块，才设置当前所选设备及原生立体声组合成员的音量。
- 所选设备全部返回有效读数时显示百分比；读数不同显示“不同”，滑块参考第一台已选设备。没有读齐时显示“—”，不把未知读数当作固定百分比。
- 没有已连接或正在连接的所选目标时禁用滑块；已连接但读数未知时仍可手动调节。保留拖动中的即时反馈、后台确认保护和固定数字槽位。

## 重新发现保留正在播放的连接

- 手动重新发现继续使用活跃的服务订阅和已知设备状态，避免一次重新扫描把正在播放的设备暂时当成离线。
- 重新发现不主动停止发送器、重新认证或重新建立 AirPlay 会话；保留单台设备和已有原生立体声组合的连接。
- 真实设备移除、连接故障或组合成员关系变化仍按各自的恢复流程处理。

## 切换音源保留 AirPlay 会话

- 切换系统输出、切换应用或切换“系统声音／指定应用”时，只替换 Windows 音频采集，保留现有扬声器会话及发送时间线。
- 清掉旧采集的待发送音频，采集切换期间发送静音。WASAPI 初始化可能造成短暂静音，不承诺无缝混音或零间隙。
- 指定应用模式仍需明确选择。没有选择、目标退出或来源暂不可用时保留连接并等待，不继续播旧应用，也不自动改播其他应用或系统声音。
- 连接保留期间仍可停止投放或使用独立测试音；有效来源恢复后继续通过原会话发送。

## 界面与版本

- 移除界面“预览版”标记，保留现有 WinUI 原生界面、立体声组合与先左后右测试音。
- 本版按 `0.4.2 → 0.4.3` 递增，仍遵守末位到 `.10` 后才进入下一中间位的规则；程序、安装包、资源和更新器版本保持一致。

## 验证与使用

发布流程要求 Rust 协议和核心回归、Windows API 生命周期、原生构建与打包、界面 smoke 和更新退出检查完整通过。新增检查区分两类证据：生产发送器和核心的协议／会话回归，以及隔离 fixture 中的原生 UI 命令行为。后者检查音量只读展示、混合和未知状态、用户真实拖动后才写入、重新发现和切换音源保留连接，以及空应用来源下的静音等待。

Windows 无设备检查使用发货核心，确认音量不可用且不产生启动确认错误；带连接的音量布局和鼠标检查使用同一原生程序加 CI 专用替代 DLL，截图以 `fixture-` 命名。fixture 中的应用、扬声器和音频均为测试数据，替代 DLL 不进入安装包。实际构建结果及截图以该版本发布附件为准；这里不把历史版本证据标为本版结果，也不新增 HomePod 真机或声学同步验证结论。

Windows 11 x64，无虚拟声卡驱动。可在设置中“检查更新”，或下载安装包；便携版请完整解压后运行。0.2.1 及以后版本支持更新前正常退出；更早版本请先在托盘菜单中退出 Airloom。
