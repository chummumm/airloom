# Airloom 0.2.1

继续处理“HomePod 亮起、波形正常但无声”的反馈，重构原生界面，修复安装更新时窗口关闭却仍驻留托盘的问题。

## 播放链路

- 补齐 gPTP 时钟协议字段：Announce 的 Path Trace、Follow_Up 的 IEEE 802.1AS 与 Apple 扩展、周期 Signaling、timescale 标志与一致的端口身份。
- 时钟就绪改为连续交换后留出稳定时间；历史累计包数不再让失去联系的时钟通过检查。
- 跟随接收端时钟的 HomePod 可以在 SETPEERS 后开始公告，修正会话建立前等待时钟造成的启动依赖。
- 从 GET `/info` 补齐缺失的设备固件信息；保留明确的发现信息，避免错误选择时钟角色。
- 事件回复兼容 HTTP/1.1 和 RTSP/1.0；正确处理只返回延迟下界或上界的接收端。
- 设置新增“复制诊断信息”：包含真实采集电平、时钟状态、音频发送和接收端响应计数，不包含设备名称、网络地址、标识、密码或密钥。

## 原生界面重构

- 按 impeccable 与 taste 方向重做 WinUI 3 布局：固定设备侧栏、清晰的音源和信号区域、独立音量控制区、优先显示更新的设置页。
- 宽窗口并排显示信号和控制，紧凑窗口纵向排列；深浅主题、系统高对比度与减少动画设置继续可用。
- 音量百分比预留固定宽度；拖动后的目标值保留到后台确认，修复旧快照覆盖滑块造成的回跳。
- 稳定设备行身份，状态和包数变化时原位更新，减少刷新引起的布局和焦点扰动。

## 更新与退出

- 安装器在替换文件前请求对应 Airloom 实例真正退出，并等待进程结束。
- 正确处理 Windows Restart Manager 的查询、取消和确认退出；普通关窗仍按原设置驻留托盘，安装退出会结束后台并移除托盘图标。
- 若旧进程未退出，显示明确错误并停止安装；不再只让窗口消失后持续等待。失败更新包仍按限定缓存范围清理。

**从 0.1.x / 0.2.0 升级这一次，请先右键系统托盘中的 Airloom →“退出 Airloom”，再运行安装包。** 旧版尚未实现新的退出协议；新安装器会识别并提示，而不会覆盖正在使用的文件。装上 0.2.1 后，后续更新即可使用新退出流程。

## 下载

- `Airloom-0.2.1-setup-x64.exe`：Windows 11 x64 安装版。
- `airloom-windows-x64-portable.zip`：退出旧版后，完整解压到新目录运行。
- `SHA256SUMS.txt`：下载文件校验值。

应用内下载的安装包会自动清理；手动下载到“下载”文件夹的安装包不属于更新缓存。

## 验证范围

发布流程要求 Linux 协议/音频测试和 Windows 原生构建全部成功。新增检查覆盖完整 gPTP 报文、延后公告的接收端、HTTP/RTSP 事件回复、独立 FFmpeg 解码、真实 WinUI/托盘退出、Restart Manager 取消和确认退出、安装退出超时与失败清理。

原生 UI 检查在 880、1100、1600 像素窗口宽度下设置 0/9/10/99/100 音量，比较关键区域的位置和尺寸，并实际拖动滑块、复制诊断、打开设置和访问 GitHub 检查更新。发布资产保留真实界面截图与检查结果。

**0.2.0 的实机结果仍是无声；0.2.1 修正了可独立验证的协议缺陷，但这里没有连接用户的 HomePod，实际恢复声音仍需本版本实机复测。** 可先播放电脑音乐，再点“试播 3 秒”；若仍无声，在保持连接时复制诊断信息。立体声组合、跨设备精确同步和实际播放延迟仍未完成实机验证。

本项目仍是开发中的开源软件。应用和安装包尚未添加发布者代码签名。
