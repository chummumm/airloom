# 多设备播放与 HomePod 立体声组合

Airloom 0.4.1 增加路线 A 的试验性实现：识别在 Apple“家庭”中已经建立的 HomePod 原生立体声组合，按一个输出目标协调两个成员。**已有组合投放仍待真实 HomePod 验证；不实现 Apple 原生组合的创建、拆散或左右声道切换。**

## 能力边界

| 功能 | 含义 | 当前状态 |
| --- | --- | --- |
| 多设备播放 | 将同一份完整双声道音频发送给多个接收端 | 已有独立会话与分发实现；不承诺样本级同步或实测声学同步 |
| 软件左右声道分配 | 一台接收左声道，另一台接收右声道，由发送端保证同步 | 尚未实现；仅拆分 PCM 不能保证两台同步发声 |
| 向已有 Apple 立体声组合投放 | 识别已经在“家庭”中组成的一对 HomePod，并协调成员与时钟 | 0.4.1 试验性实现；本机双接收端协议测试通过，HomePod 真机及声学同步待验证 |
| 在 Airloom 中管理 Apple 原生组合 | 创建、拆散组合，或交换左右声道 | 尚未实现 |

Apple 将控制中心里的多房间选择与立体声组合分别介绍：前者选择在哪些设备播放，后者让两台 HomePod 分别承担左右声道。参见 [Apple 对两项功能的说明](https://www.apple.com/newsroom/2018/05/ios-11-4-brings-stereo-pairs-and-multi-room-audio-with-airplay-2/)。

## 在 Apple“家庭”中建立组合

按 [Apple 官方 HomePod 使用手册](https://support.apple.com/zh-cn/guide/homepod/apd1ed62a52a/homepod)：

1. 使用两台**相同机型**的 HomePod，例如两台 HomePod mini、两台 HomePod（第 1 代）或两台 HomePod（第 2 代）。
2. 在“家庭”中将两台设备分配至**同一房间**。
3. 在 iPhone 或 iPad 打开“家庭”，选择一台 HomePod，进入设置，选择“创建立体声组合”。
4. 建立后，可在组合的“音频设置”中切换左右声道；“取消配件组合”用于拆散。

这些步骤建立的是 Apple 设备上的组合，**不表示 Airloom 已验证对该组合的投放**。不能把一台 HomePod 与一台 HomePod mini，或不同代的 HomePod，按上述官方方式组成同一立体声对。

## 0.4.1 的实现

- [设备发现](../crates/airloom-airplay/src/discovery.rs)持续订阅 AirPlay/RAOP 服务事件，保留服务来源并合并物理设备。只在 HomePod 的 `AudioAccessory` 机型上接受有效、非零的 UUID `tsid`；不按 `gid`、名称或 `igl` 猜测组合。没有应用层周期补查。
- 核心把组合映射为稳定逻辑 ID `stereo:<tsid>`，显示一张卡和成员状态。一个成员未发现时保留已知成员并标为离线；明确组合信息变化时先停止旧组合，防止继续使用过时成员关系。
- 两台分别完成认证和会话建立后，调用 `Sender::prepare_native_group` 检查同一原生组、两台不同设备、共同且由发送端控制的 PTP 时钟、全新会话和可兼容延迟。检查失败会报错，不静默降级成独立双机。
- 两台收到相同首块和后续完整双声道 PCM，使用共同 RTP 与起播时间映射。Airloom 不拆分左右音频，不更改“家庭”中的声道角色；接收端是否按原生角色实际发声仍需真机测试。
- 任何成员发送落后、队列不连续或失败会停止并重新连接整个组合。独立设备及其他组合不受影响。重连沿用已有的有界重试，不加入设备发现补查。
- 密码按具体成员提示和保存。一个组合单独选中时显示“组合音量”；从 0.4.3 开始先读取各成员现有音量，只有手动调节才同时设置两台。成员音量不同时显示“不同”，未读齐显示“—”，连接时不自动统一。
- 选择原生组后，现有测试音按钮输出 3 秒先左、短静音、后右测试音，方便在真实设备上核对 Apple 的声道角色。

0.4.3 的手动重新发现和音源切换保留现有组合及两条成员会话。更换 Windows 采集期间可能短暂静音；没有明确应用选择时保持连接并等待。真实成员离线、发送故障和原生组合关系变化仍触发相应的组级恢复。

目前使用保守的发送端 PTP 时钟路径。要求接收端作为时钟主机或其他拓扑的组合，可能被拒绝并需要继续研究。没有盲目更改 SETUP 多选、组长或 relay 标志，也不假设仅连接一个“组长”就能播放整组。

公开协议研究说明 `gid`、`pgid` 等发现字段会随播放状态变化，因此不能只凭一个分组字段、相同名称或两台被同时选中，就推断原生立体声关系。参见 [OpenAirPlay 服务发现研究](https://openairplay.github.io/airplay-spec/service_discovery.html)。[OwnTone 的组合调查](https://github.com/owntone/owntone-server/issues/1413)也分别讨论了界面组合、成员传输及 Apple TV 家庭影院路径；其中的特定固件观察不作为 Airloom 的通用保证。

## 测试与剩余验证

本机协议测试使用两个独立 TCP/UDP 接收端，验证完整左右声道都抵达两成员、首 RTP 相同、不同接收延迟能取可接受的共同值、播放时间映射在样本舍入范围内一致，以及落后成员使整个组失败且没有独立重锚。核心测试覆盖一组一卡、原子选择、共同音频块、整组重试、认证保留、临时缺席和组信息变化。UI fixture 检查组卡、成员状态、音量与隐藏偏好。

这些是软件与协议层验证，不能代替真实 HomePod。真机需要核对：组合发现、两个成员的认证、左右测试音、无相互抢占、持续至少 30 分钟的播放、整组音量和停止、单台离线/重连；记录机型、固件及网络条件。Apple TV 默认输出/家庭影院绑定组另列，不能由普通原生配对测试代替。

后续若研究软件左右声道模式，仍需独立定义支持范围。可参考 [Music Assistant 的原生组合与软件声道分配说明](https://www.music-assistant.io/faq/how-to/#create-a-stereo-pair)及[发送端时钟与组启动设计](https://github.com/music-assistant/airplay-cli/blob/main/DESIGN.md)作为工程研究；本项目实现与测试不构成第三方或 Apple 的兼容性认证。
